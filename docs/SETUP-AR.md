# دليل التشغيل بأمر واحد

هذا الدليل يشرح، خطوة بخطوة، كيف تُحوِّل أي جهاز — macOS أو Windows أو Linux — إلى خادم
يعمل عليه نظام إدارة العقارات. كل ما تحتاجه أمر واحد.

النظام يعمل محليًا بالكامل. لا يخرج أي مرفق أو نص مستخرج منه إلى أي جهة خارجية.

---

## ١. قبل أن تبدأ

| المطلب | التفاصيل |
| --- | --- |
| نسخة من المشروع | مجلد المشروع كاملًا على الجهاز |
| اتصال بالإنترنت | مطلوب في التشغيل الأول فقط، لتنزيل البرامج المطلوبة |
| صلاحيات التثبيت | على Linux قد يطلب الأمر صلاحية `sudo` لتثبيت الحزم |
| قاعدة البيانات | يمكنك استخدام PostgreSQL 17 المثبّت على الجهاز مباشرة، أو تشغيله عبر Docker. لا تحتاج إلى Docker عند اختيار الوضع الأصلي `native` |

**ملاحظة مهمة على Windows:** في وضع Docker، قد يحتاج تثبيت Docker Desktop إلى إعادة تشغيل
الجهاز. وفي الوضع الأصلي، إذا لم يكن PostgreSQL 17 مثبتًا، يتوقف الأمر ويعطيك أمر التثبيت
الرسمي الذي تشغّله بصلاحيات المدير، ثم تعيد تشغيل أمر الإعداد. لا يضع الأمر كلمة مرور مستخدم
`postgres` في سطر الأوامر.

---

## ٢. الأمر الواحد

افتح الطرفية (Terminal) داخل مجلد المشروع، ثم نفِّذ الأمر الخاص بنظامك:

### macOS و Linux

```bash
bash scripts/setup.sh
```

أو، وهو نفس الشيء:

```bash
make setup
```

### Windows

افتح PowerShell داخل مجلد المشروع، ثم:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\setup.ps1
```

**هذا كل شيء.** انتظر حتى ينتهي الأمر. في التشغيل الأول قد يستغرق عدة دقائق لأنه ينزّل
البرامج المطلوبة ويبني التطبيق.

إذا لم تحدّد وضع قاعدة البيانات، يبحث الأمر عن خادم PostgreSQL مثبت على الجهاز ويعمل ويمكن
الوصول إليه. إذا وجده يستخدمه مباشرة؛ وإلا يستخدم Docker. ويطبع في مرحلة `Preflight` الوضع
الذي اختاره وسبب الاختيار في سطر واحد.

للاختيار الصريح:

```bash
# على macOS و Linux: PostgreSQL المثبّت على الجهاز
bash scripts/setup.sh --db=native

# على macOS و Linux: PostgreSQL داخل Docker
bash scripts/setup.sh --db=docker
```

```powershell
# على Windows: PostgreSQL المثبّت على الجهاز
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\setup.ps1 --db=native

# على Windows: PostgreSQL داخل Docker
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\setup.ps1 --db=docker
```

في وضع `native` لا يفحص الأمر Docker ولا يشغّله. يشترط PostgreSQL بالإصدار الرئيسي 17؛ وإذا
وجد إصدارًا رئيسيًا آخر يتوقف ولا يحاول ترقيته أو إرجاعه إلى إصدار أقدم. على macOS يثبّت
`postgresql@17` عبر Homebrew ويديره بواسطة `brew services`. وعلى Linux يستخدم مدير الحزم
وخدمة النظام. ثم يضبط PostgreSQL ليستمع على `127.0.0.1:5432` فقط، وينشئ قاعدة `pms` ودور
`pms_owner` المالك لها. وإذا كانت مستودعات Debian أو Ubuntu لا توفّر الإصدار 17 (أرشيف jammy
يوفّر 14 و noble يوفّر 16) يضيف الأمر مستودع PostgreSQL الرسمي (PGDG) للإصدار المكتشف ثم يثبّت
منه. على Windows يدير خدمة PostgreSQL 17 بعد إتمام التثبيت الرسمي.

## ٣. ماذا يفعل هذا الأمر؟

يمر الأمر بسبع مراحل، ويطبع اسم كل مرحلة وهو ينفّذها:

| المرحلة | ما يحدث فيها |
| --- | --- |
| `Dependencies` | يتحقق من البرامج المطلوبة ويثبّت الناقص منها فقط: Go و Node.js و OpenSSL، بالإضافة إلى Tesseract مع بيانات اللغة العربية و Poppler لقراءة نصوص ملفات PDF؛ ويضيف Docker أو PostgreSQL 17 بحسب الوضع المختار، أو يعطي أمر التثبيت اليدوي الآمن على Windows |
| `Configuration` | ينشئ ملف `.env` إن لم يكن موجودًا، ويملأ القيم الفارغة، ويحدّد فقط كلمتي التطوير الافتراضيتين ليدوّرهما بعد تحديث الجداول |
| `TLS` | ينشئ شهادة أمان ذاتية التوقيع للاتصال المشفَّر عبر HTTPS |
| `Database` | يشغّل PostgreSQL بالطريقة المختارة، ويطبّق تحديثات الجداول، ثم يثبّت كلمات مرور أدوار قاعدة البيانات المولّدة |
| `Seed administrator` | ينشئ حساب المدير فقط — **ولا يُحمّل أي بيانات تجريبية** |
| `Build` | يبني نسخة الإنتاج من الواجهة والخادم |
| `Start` | يشغّل الخادم وينتظر حتى يستجيب، ثم يطبع رابط الدخول |

عند النجاح ستظهر لك رسالة مثل:

```
Sign in at: https://localhost:8443
LAN URL: https://192.168.1.29:8443
Administrator username: admin
The administrator password is in .env.
```

## ٤. تسجيل الدخول

1. افتح المتصفح على العنوان: **https://localhost:8443**
2. **اسم المستخدم:** `admin`
3. **كلمة المرور:** موجودة في ملف `.env` في مجلد المشروع، أمام المتغير `PMS_ADMIN_PASSWORD`

لقراءة كلمة المرور:

```bash
# على macOS و Linux
grep PMS_ADMIN_PASSWORD .env
```

```powershell
# على Windows
Select-String -Path .env -Pattern PMS_ADMIN_PASSWORD
```

**لماذا لا يطبع الأمر كلمة المرور على الشاشة؟** لأن ما يُطبع على الشاشة قد يُحفظ في سجلات
الطرفية. لذلك تُكتب كلمة المرور في ملف `.env` وحده، وهو ملف مستثنى من المستودع ولا يُرفَع معه.

**إذا أردت اختيار كلمة المرور بنفسك:** ضع القيمة التي تريدها في `PMS_ADMIN_PASSWORD` داخل
`.env` **قبل** تشغيل الأمر (١٢ حرفًا على الأقل)، وسيستخدمها الأمر كما هي. وإن تركت الحقل
فارغًا فسيولّد الأمر كلمة مرور عشوائية ويكتبها هناك.

## ٥. تحذير المتصفح عن الشهادة

الشهادة ذاتية التوقيع، لذلك سيعرض المتصفح تحذيرًا في أول زيارة. هذا متوقع في التشغيل المحلي.
اختر "متابعة" أو "Advanced ← Proceed" للدخول.

---

## ٦. الدخول من جهاز آخر على نفس الشبكة

استخدم رابط `LAN URL` الذي طبعه الأمر، مثل `https://192.168.1.29:8443`.

إذا لم يفتح الرابط من الجهاز الآخر، فالسبب في الغالب أحد اثنين:

- **جدار الحماية** على جهاز الخادم يمنع المنفذ `8443` — اسمح به يدويًا.
- **قيمة `PMS_LISTEN_ADDR`** في `.env` تسمح بالاتصال المحلي فقط. اجعلها `0.0.0.0:8443`،
  ثم أعد تشغيل الأمر. (إذا كانت مضبوطة على الاتصال المحلي فقط، ينبّهك الأمر بذلك ولا يطبع
  رابط الشبكة أصلًا.)

## ٧. إيقاف الخادم وإعادة تشغيله

### إعادة التشغيل

نفِّذ نفس الأمر مرة أخرى. الأمر آمن للتكرار: يوقف الخادم القديم ثم يشغّل الجديد، ولا يمسّ
بياناتك ولا يعيد إنشاء ما هو موجود.

### الإيقاف

```bash
# على macOS و Linux
kill "$(cat ~/.local/state/pms/pms-api.pid)"
```

```powershell
# على Windows
Stop-Process -Id (Get-Content "$env:LOCALAPPDATA\pms\pms-api.pid")
```

### مكان السجلات

| النظام | المسار |
| --- | --- |
| macOS و Linux | `~/.local/state/pms/pms-api.log` |
| Windows | `%LOCALAPPDATA%\pms\pms-api.stdout.log` و `pms-api.stderr.log` |

## ٨. خيارات إضافية

| الخيار | الاستخدام |
| --- | --- |
| `--db=native` | يستخدم PostgreSQL 17 المثبّت على الجهاز مباشرة، ولا يحتاج إلى Docker |
| `--db=docker` | يستخدم PostgreSQL 17 داخل Docker كما كان يفعل الإعداد سابقًا |
| `--no-start` | ينفّذ كل شيء دون تشغيل الخادم في النهاية |
| `--skip-deps` | يتخطى مرحلة تثبيت البرامج، إذا كنت تديرها بنفسك |

مثال:

```bash
bash scripts/setup.sh --no-start
```

يمكن جمع الخيارات، مثل:

```bash
bash scripts/setup.sh --db=native --no-start
```

## ٩. حل المشاكل الشائعة

كل رسالة خطأ من الأمر تذكر لك الخطوة التالية بالتحديد. وهذه أكثر الحالات تكرارًا:

| الرسالة | السبب والحل |
| --- | --- |
| `port 8443 is already in use` | برنامج آخر يستخدم المنفذ. أوقفه، أو غيّر `PMS_LISTEN_ADDR` في `.env` إلى منفذ آخر |
| `Docker did not become ready` | Docker غير مُشغَّل. افتح Docker Desktop (أو شغّل خدمة Docker على Linux) وانتظر حتى يعمل، ثم أعد المحاولة |
| `PostgreSQL did not become ready` | قاعدة البيانات لم تُقلع. في وضع Docker راجع سجلها: `docker compose --env-file .env -f infra/docker-compose.yml logs postgres` |
| `version 17 is required` | الوضع الأصلي وجد إصدارًا رئيسيًا آخر من PostgreSQL. رقِّه أو أزله بنفسك واجعل الإصدار 17 هو الخادم المحلي؛ الأمر لا يجري ترقية أو إرجاعًا تلقائيًا |
| `bootstrap access as postgres failed` | على Windows افتح جلسة PowerShell كما توضّح رسالة الخطأ، واقرأ كلمة مرور `postgres` بأداة `Get-Credential` إلى `PGPASSWORD` مؤقتًا، ثم أعد تشغيل الإعداد واحذف المتغير من الجلسة |
| `PMS_KEK must be base64 for exactly 32 bytes` | مفتاح التشفير في `.env` تالف. **أعِد المفتاح الصحيح ولا تولّد بديلًا** — اقرأ التحذير في القسم التالي |
| `PMS_ATTACHMENT_STORE is inside the repository` | مجلد المرفقات يجب أن يكون خارج مجلد المشروع. صحّح المسار في `.env` |
| فشل تثبيت Go أو Node | نسخة نظامك أقدم من المطلوب. ثبّتهما من موقعيهما الرسميين ثم أعد تشغيل الأمر |

## ١٠. تحذيرات أمنية مهمة

**١. لا تحذف ولا تغيّر `PMS_KEK` في `.env` أبدًا.**
هذا هو مفتاح تشفير المرفقات والحقول السرية. إذا فُقد، تصبح كل المرفقات المخزَّنة غير قابلة
للقراءة نهائيًا، ولا توجد وسيلة لاستعادتها. الأمر مصمَّم بحيث لا يستبدل هذا المفتاح إذا كان
موجودًا، لكن حذفه يدويًا يعني فقدان البيانات.

**٢. لا ترفع ملف `.env` إلى أي مستودع ولا ترسله لأحد.**
يحتوي على مفتاح التشفير وكلمات المرور. الملف مستثنى من المستودع بالفعل.

**٣. كلمات مرور قاعدة البيانات لا تُطبع.**
إذا كانت قيمة `PMS_DATABASE_OWNER_URL` أو `PMS_DATABASE_APP_URL` غائبة أو فارغة، يولّد الأمر
لكل دور كلمة مرور ستّ عشرية عشوائية مستقلة، ويضعها داخل رابط الاتصال نفسه في `.env` فقط. وإذا
وجد كلمة التطوير القديمة المطابقة تمامًا لـ `dev_only_owner_pw` أو `dev_only_app_pw`، يستبدلها
مرة واحدة بعد تطبيقها على الخادم ويطبع إشعارًا بالدوران دون طباعة السر. أما أي كلمة مرور أخرى
فيعدّها اختيارًا من المشغّل ولا يغيّرها ولا يكرّر التحذير بشأنها. لذلك لا يدوّر التشغيل الثاني
الناجح كلمات المرور من جديد.

**٤. خذ نسخة احتياطية من ثلاثة أشياء معًا:**

- ملف `.env` (فيه مفتاح التشفير)
- مجلد المرفقات المحدَّد في `PMS_ATTACHMENT_STORE`
- قاعدة البيانات

النسخة الاحتياطية من المرفقات وحدها بلا `PMS_KEK` عديمة الفائدة، لأن الملفات مشفَّرة.
